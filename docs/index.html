Overview

Enshrouded Server Manager is a single dbghelp.dll that loads with your Enshrouded dedicated server. It runs inside the server and holds the secure WebSocket to Takaro itself. Only the server needs it; players join as usual.

Player EventsJoin, leave, chat, deaths and kills tracked in Takaro in real time.
Admin ActionsBroadcast, give items, teleport, kick/ban/unban, read inventory & location.
Character LevelsEach player's character name and level, ready for Takaro modules through the levels command.
Discord ChatGame chat to Discord and Discord back into game chat through Takaro modules.
One DLL does it allCopy one file next to the server and paste your Takaro token.

Supported Versions

Supports Enshrouded 1.0 (game builds 1267041 and 1269579) and the earlier build 1024233, on Windows and under Wine/Proton on Linux. It is a community connector, with its source in gettakaro/connectors; every new version is published to this page's releases automatically.

Install

  1. Download takaro-enshrouded-plugin.zip from the latest release.
  2. Stop the server and copy dbghelp.dll from the zip next to enshrouded_server.exe: 
    enshrouded_server.exe
dbghelp.dll                  (the mod)
takaro\plugin.json            (created at the first start — edit this)
  3. Linux (Wine / Proton): required. Set WINEDLLOVERRIDES=dbghelp=n,b on the server, or the mod never loads. See Linux: Wine & Proton.

Linux: Wine & Proton

The mod works under 64-bit Wine (wine64 or a WoW64 build) and Proton, but it needs one setting. Wine and Proton ship their own dbghelp.dll and by default use it instead of the one next to enshrouded_server.exe. Without the setting the mod is never loaded: no takaro\plugin.log, no [Takaro] lines in the console, and the server runs as if nothing were installed.

Running Wine yourself (no Docker)? The simplest fix is to set it once in Wine's own settings; nothing else needs to change. As the same Linux user that runs the server (add WINEPREFIX=/path/to/prefix in front if you use your own prefix):

winecfg

→ Libraries tab → type dbghelp under "New override for library" → Add → select it → Edit → Native then Builtin → OK. Or the same in one command:

wine reg add 'HKCU\Software\Wine\DllOverrides' /v dbghelp /d native,builtin /f

Then restart the server. Otherwise, set this environment variable on the game server so Wine loads the mod first:

WINEDLLOVERRIDES=dbghelp=n,b
How your server runsWhere to set it
Started by handWINEDLLOVERRIDES="dbghelp=n,b" wine64 enshrouded_server.exe (or wine)
systemd serviceUnder [Service]: Environment=WINEDLLOVERRIDES=dbghelp=n,b, then systemctl daemon-reload and restart
Docker ComposeUnder environment: of the server: WINEDLLOVERRIDES: "dbghelp=n,b"
docker run-e WINEDLLOVERRIDES="dbghelp=n,b"
Unraid templateEdit the container, add a Variable: key WINEDLLOVERRIDES, value dbghelp=n,b
Pterodactyl, AMP or another panelThe server's environment / startup variables
Your own start scriptexport WINEDLLOVERRIDES="dbghelp=n,b" before wine enshrouded_server.exe

If your image already sets WINEDLLOVERRIDES, add the mod to that value with a semicolon instead of replacing it, for example dbghelp=n,b;mscoree,mshtml=. Restart the server after the change.

Can't set the variable? Some images overwrite it in their start script. Store the same setting once in the server's Wine prefix instead (run it as the user the server runs as, with the server's WINEPREFIX; for Docker, inside the container), then restart the server: 
wine reg add 'HKCU\Software\Wine\AppDefaults\enshrouded_server.exe\DllOverrides' /v dbghelp /d native,builtin /f
A prefix that is recreated (new container volume, reinstall) loses this; the variable does not.

Check that it loaded. takaro\plugin.log appears and shows connected to Takaro. If there is no plugin.log at all, Wine still used its own copy. To see which one it used, start the server once with WINEDEBUG=+loaddll added: a Loaded line for the dbghelp.dll in the server folder ending in : native means the mod loaded; a line for C:\windows\system32\dbghelp.dll ending in : builtin means the setting did not reach the server. Remove WINEDEBUG again afterwards.

Wine versions. Wine development releases from 11.8 on usually load the mod without the setting; older Wine, including stable Wine 11.0, and Proton need it. Set it on every version; it does no harm.

Configure

  1. In Takaro: Game servers → Create new game server → Generic, copy your registration token. The server appears in Takaro by itself when it connects.
  2. Start the server once; it creates takaro\plugin.json. Paste your token, put your server's name into identityToken and save — the mod connects within a few seconds:
{
  "registrationToken": "paste-your-token-here",
  "identityToken": "name-your-server"
}

Takaro creates the game server under that name and recognizes it by it from then on, so pick a name no other server in your Takaro uses and keep it.

Start & Verify

  1. Start the server. dbghelp.dll loads with it automatically.
  2. takaro\plugin.log shows connected to Takaro as "<name>". No plugin.log at all means the server never loaded the mod: on Linux, see Wine & Proton.
  3. The server shows online in the Takaro dashboard within seconds.
  4. Have a player join & chat — player-connected and chat-message appear in Takaro.

Game Updates

Everything that changes between game builds lives in takaro\enshrouded-gamedata.json, one section per build. The log prints game build: <n> at start. After a game update the mod works out the new build's section from the game itself, saves it to that file with the note derived automatically and uses it, so the same DLL keeps working. The item list follows the same way: on a new build the mod rebuilds it once from the server's own enshrouded_server.kfc and saves it as takaro\enshrouded-items.json, so giving items and the item catalogue keep working. Any feature it could not set up shows as degraded in Takaro while the rest keeps running, and a newer release brings it back.
